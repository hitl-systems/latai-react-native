# latai for React Native

JSI glue over the latai C ABI (`include/latai.h`, API v2) and a TypeScript API: `Runtime.open`,
`run`, `runStream` (an async iterable), pack management, `listen` (speech streams) and `LataiError`
with a category. Apache-2.0 OR MIT. **Status: written without React Native, Xcode or the Android
NDK; the TypeScript type-checks and its logic runs against a mock, the C++ passes `clang
-fsyntax-only` against stubs of the JSI headers; nothing ran on a device**. Treat it as a published design, not a shipping path yet. Bridgeless mode (the default from React Native 0.76) is **not** supported yet.

```ts
import { Runtime } from 'latai-react-native';

const rt = await Runtime.open({ dataDir });                  // once per process
await rt.install('/path/x4r-l8.gguf');
const req = { pack: 'x4r-l8', inputs: { type: 'text', text: 'hello' }, output: { max_tokens: 32 } } as const;

const res = await rt.run(req);                               // rejects with LataiError on finish: 'error'
for await (const e of rt.runStream(req)) {                   // events arrive on the JS thread
  if (e.event === 'delta') console.log(e.text);              // break cancels the request
}
const s = await rt.listen({ pack: 'asr' });                  // speech
await s.push(pcm16le);                                       // Uint8Array | ArrayBuffer
await s.close();
await rt.close();
```

Errors are `LataiError` (`number`, `code` "E0206", `message`, `hint`, `details`, `category`). Same rules
as the Python and Node SDKs:

- `run` **rejects** with the typed error when the response ends `finish: 'error'`, with the whole
  response in `err.response` (`latai.started` is false in it when the engine was never called). Pass
  `{ raiseOnError: false }` to get the response back instead (`orThrow(response)` raises it later);
  `cancelled` and `length` are normal results, and a request that does not parse (`E0301`) always
  rejects. Options are an object: `rt.run(req, { requestId, raiseOnError })`.
- `runStream` **never rejects with an event**: an `error` event, or a `final` with `finish: 'error'`, is
  yielded and the iteration then ends normally. Only a call that fails before any terminal event (a
  closed runtime, `E0302`, `E0303`) makes the iteration reject with a `LataiError`.
- `listen` rejects when the stream cannot open, with the `error` event in `err.events`. After it
  opened, a push that ends the stream with an error rejects with that error; the `final` is still on
  `events`.

The wire types (`Request`, `Response`, `Event`, `StreamEvent`, `PackInfo`, ...) are
`src/types.g.ts`, generated by `python3 sdk/tools/gen_types_ts.py` (wire names, snake_case).

## How it works

`LataiModule` (Java on Android, Objective-C++ on iOS) has one synchronous method, `install()`,
which hands the `jsi::Runtime` and the JS `CallInvoker` to `cpp/LataiJsi.cpp`. That installs
`global.__latai`, a plain object of host functions (typed by `src/native.ts`). Each blocking call
runs on a native worker thread and its result and every event come back on the JS thread via
`invokeAsync`, in order; `cancel` and `streamCancel` are synchronous. There is no TurboModule spec,
so the same code serves the old architecture and the new one through the interop layer.

## Build and run on a device

Needs a React Native 0.73-0.75 app (not bridgeless), Node, the Android SDK/NDK 26 or Xcode 15, and
the mobile build of liblatai, which is not published yet.

1. **Add the package** to the app: `npm install github:hitl-systems/latai-react-native`. Autolinking finds `latai-react-native.podspec` and `android/`.
2. **Place the library.**
   - Android: `android/src/main/jniLibs/<abi>/liblatai.so` (`arm64-v8a`,
     `x86_64`). The CMake file links the glue against it; the module loads it.
   - iOS: `ios/Frameworks/latai.xcframework` (static or dynamic, no headers inside).
     Then `cd ios && pod install`.
3. **Use the example component:** copy `example/App.tsx` over the app's `App.tsx`.
4. **Put a pack on the device** (a signed `.gguf` and its `.minisig` in the app's documents
   folder, signed by a trusted key) and set `PACK` in `App.tsx`.
5. **Run:** `npx react-native run-android` or `npx react-native run-ios`. Tap Ask; text streams in;
   Stop ends the request.

## Check without a device

From this folder:

```text
npm install typescript@5.6.3 --no-save && npm run typecheck
clang++ -std=c++17 -fsyntax-only -Wall -Wextra -I include -I cpp -I cpp/stubs cpp/LataiJsi.cpp
```

`cpp/stubs/` and `test-stubs/` are test aids written from memory of the real headers; delete them
from any copy you ship. `node_modules` is ignored by git.
